# Phone media picker recovery

Jake asked to continue the phone media-to-quote workflow. The current identity hook deliberately clears verified identity/readiness on window focus and visibility return. Both quote media components tie local selections to that temporary readiness state. Consequently returning from a native picker can discard a valid arriving file or existing selection. This batch repairs local media continuity without changing the shared identity hook or granting access while verification is pending.

## Design

Keep a component-local binding to the last verified office account, exact authentication ownership and quote target. A temporary loading snapshot may retain that binding only while the same session/epoch, mode and target remain. Failed verification, a different verified organisation/role/user, logout, token replacement or target changes retire it permanently; switching back cannot revive the old binding. The binding authorises local file receipt only. Existing readiness, role, ownership and server membership checks still govern all preparation, transcription, AI requests and applying reviews.

Separate the local-media identity from request scope. Local files and completed small photo copies/recording preparation/checked transcripts can survive a same-session readiness refresh or edits to typed notes. Hide media while account verification is pending. Abort pending work, discard old AI scope results and reject retained request/apply callbacks after any readiness or note change. Once the same office identity is verified again, restore the local evidence and enable fresh explicit actions. Job evidence selected from saved cloud records retains its existing stricter invalidation.

The real mounting chain also needs continuity: `CloudAccessGuard` normally unmounts route children during identity loading, and Quote Builder normally unmounts its content during collection loading. Only the exact `/ai/quote-builder` route may keep its previously authorised same-session subtree mounted, hidden and inert while identity is pending. It remains behind the same role/path policy; initial loading, failed verification, replaced sessions and denied roles do not retain it. Other routes keep their existing loading/unmount behaviour. Quote Builder similarly keeps an already loaded media subtree hidden/inert while its collections refresh. Changed workspace identity (including normalised email) gets a new keyed subtree. No protected content is displayed or made interactive while checks are pending.

Native picker events captured before focus refresh can arrive while checks are pending. Accept valid local files only if the captured binding/session still matches the live component target, append photos to the latest held collection and cancel obsolete work. Invalid batches preserve previous evidence; account/target/session changes reject the event. The video picker follows the same ownership boundary and cancels replaced preparation. No file receipt triggers an API call.

## Boundaries

No shared authentication-policy changes, new persistence, credentials, dependencies, server/API schema, paid requests, cloud record writes or production release. The six-image/byte/duration limits remain. Account refresh failure deliberately clears local evidence. Physical iPhone/Android picker timing, codecs and funded live AI remain acceptance checks; synthetic state transitions demonstrate the fix without claiming device certification. Publish only to the authorised jr-os-v2 preview after tests, lint, build, independent review and green CI.
